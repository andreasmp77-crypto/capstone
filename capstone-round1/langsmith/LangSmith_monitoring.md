## 1. Objective

This monitoring sample demonstrates how LangSmith can be used to provide
observability and transparency for an AI-powered maritime crew change
risk assessment workflow.

The AI component receives operational crew change data and generates a
structured risk briefing for a human operations manager.

The monitoring experiment was designed to track:

- Individual AI executions (traces)
- Input and output data
- Model used
- Response latency
- Token consumption
- Estimated API cost
- Structured AI recommendations

The AI assessment uses the same operational prompt logic as the Crew
Travel Copilot n8n workflow.

## 6. What the Monitoring Demonstrates

The LangSmith monitoring implementation demonstrates several important
AI observability capabilities:

### Transparency

Each AI execution can be inspected individually. This makes it possible
to understand what operational information was provided to the model and
what recommendation it produced.

### Traceability

Each crew change assessment is recorded as an individual trace, allowing
specific AI decisions to be linked back to the operational case.

### Performance Monitoring

Latency is visible for every model execution. This could help identify
performance issues if the application were scaled to process larger
numbers of crew changes.

### Cost Observability

Token usage and estimated API cost are captured per execution. This is
important for evaluating the financial viability of an AI solution in a
production environment.

### Human Oversight

The AI is positioned as a decision-support tool rather than an autonomous
decision-maker. The prompt explicitly instructs the model not to modify
the deterministic risk score or contradict the provided risk level.

For High-risk cases, the AI is instructed to recommend human review.

This LangSmith monitoring sample demonstrates how observability can be
added to the AI component of the Crew Travel Copilot.

The experiment successfully monitored five operational crew change cases
